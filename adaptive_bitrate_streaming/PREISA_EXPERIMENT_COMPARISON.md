最后更新：`2026-05-06`

## 记录范围

这份文档是当前 `llama_small + semantic_reprogram` ABR 实验线的正式中文记录。

当前仍然值得继续比较、继续投入的主线只有 4 条：

1. `semantic_only`
2. `preisa_prev_ar_h8_hd1024_maskprevreward`
3. `hmix_preisa_prev_ar_h8_hd1024_maskprevreward`
4. `hmix_v2lite_preisa_prev_ar_h8_hd1024_maskprevreward`

更早的一些探索性分支不再作为主比较对象，只在文末附录保留归档。

## 指标说明

- `best_return`：训练过程中出现过的最佳验证回报
- `test mean_reward`：按照项目内 `calc_mean_reward()` 逻辑统计的测试平均奖励
- `bitrate`：测试阶段平均码率
- `rebuf`：测试阶段平均重缓冲时间
- `smooth`：测试阶段平均平滑性惩罚
- 下文所有测试统计都与代码口径保持一致：每条 trace 的第一条 reward 不计入平均

## 主线定义

### `semantic_only`

- 不使用 pre-align intra-step attention
- 不使用 TimeMixer
- 纯语义重编程基线

### `maskprevreward`

- 上下文形式为 `state + prev_action + prev_reward`
- 开启 pre-align intra-step attention
- mask 模式为 `state_to_prev_reward`
- 当前最强的非 TimeMixer 完整主线

### `hmix`

- 在 `maskprevreward` 基础上加入原始版 history multiscale mixer
- 即原始 TimeMixer 实现
- 上限更高，但 seed 波动明显

### `hmix_v2lite`

- 是对原始 `hmix` 的结构性收缩版本
- 只混合 `throughput history`
- 尺度从 `6 -> 3 -> 2 -> 1` 缩成 `6 -> 3`
- residual gate 从单标量改成按维度的向量 gate
- 当前目标是：尽量保留原始 `hmix` 的高上限，同时降低 seed 敏感性

## 核心结论

1. 当前单次最优结果仍然是 `hmix_v2lite seed=100003`，`test mean_reward = 0.9510`。
2. `hmix_v2lite` 现在已经完成了 3 个 seed，且 3-seed 均值达到 `0.9248`，正式超过 `maskprevreward` 的 `0.9051`。
3. 原始 `hmix` 已经证明 TimeMixer 方向本身有价值，但它的核心问题是 seed 敏感性过高；`hmix_v2lite` 则基本解决了这个问题。
4. 到当前为止，`hmix_v2lite` 已经可以视为新的主线候选，而且从现有结果看，它不只是“单点最强”，也是“整体最强”。

## 各主线分析

### 1. `semantic_only`

`semantic_only` 依然是一个不能忽视的强基线，因为它的最佳 seed 结果仍然达到 `0.9167`。  
它的问题不在于上限不够，而在于波动偏大：`100001` 只有 `0.7923`，而 `100003` 可以到 `0.9167`。这说明纯语义重编程是有效的，但鲁棒性一般。

### 2. `maskprevreward`

`maskprevreward` 仍然是当前最干净、最稳定、最适合作为主比较对象的非 TimeMixer 主线。

其 3 个已完成 seed 为：

- `100001`：`0.8902`
- `100002`：`0.9076`
- `100003`：`0.9175`

对应 3-seed 均值为 `0.9051`，显著高于 `semantic_only`。  
它的主要优势在于：通过更好的重缓冲控制来提升 QoE，同时没有把码率压得过低。因此，到目前为止，它依然是最公平、最可靠的“稳定基线”。

### 3. 原始 `hmix`

原始 `hmix` 的意义在于，它第一次证明了 TimeMixer 这条路能把上限抬上去；但同时也暴露出实现层面的稳定性问题。

其 3 个已完成 seed 为：

- `100001`：`0.8206`
- `100002`：`0.8631`
- `100003`：`0.9212`

对应 3-seed 均值只有 `0.8683`，明显低于 `maskprevreward`。  
因此，这条线给出的结论非常清楚：

1. 单次最优结果更强
2. 但均值更差
3. 且不同 seed 之间的策略风格漂移很大

也就是说，原始 `hmix` 不是“没用”，而是“有上限，但不稳”。

## `hmix_v2lite` 记录

### 结构概述

`hmix_v2lite` 是当前的保守版 TimeMixer 重设计。

实际落下去的结构改动有 3 个：

1. TimeMixer 只作用在 `throughput history`
2. multiscale 路径缩成 `6 -> 3`
3. residual 注入由单标量 gate 改为按维度的向量 gate

这版设计的核心目标很明确：

- 保住原始 `hmix` 已经展示出来的高上限
- 尽量压低原始 `hmix` 的 seed 敏感性

### `seed=100002`

结果如下：

- `best_return = 4.5240`
- 最优 epoch：`50`
- `test mean_reward = 0.9148`
- `bitrate = 1096.9`
- `rebuf = 0.0227`
- `smooth = 0.0843`

和原始 `hmix 100002` 对比：

- 原始 `hmix 100002`：`0.8631 / 1014.0 / 0.0110 / 0.1035`
- `v2lite 100002`：`0.9148 / 1096.9 / 0.0227 / 0.0843`

这说明：

1. 这是一个典型的“修复型”seed。
2. `v2lite` 把原始 `hmix 100002` 最明显的问题修回来了，尤其是码率和平滑性。
3. 它确实付出了更高 `rebuf` 的代价，但整体 reward 提升幅度很大，说明这次权衡是值得的。

再和 `maskprevreward 100002` 对比：

- `maskprevreward 100002`：`0.9076 / 1017.8 / 0.0092 / 0.0708`
- `v2lite 100002`：`0.9148 / 1096.9 / 0.0227 / 0.0843`

这说明：

1. `v2lite` 不只是修复了旧版 `hmix`，而且已经小幅超过非 TimeMixer 主线。
2. 这次赢分的主要来源是更高的码率。
3. 代价是 `rebuf` 更高，`smooth` 也略差。

### `seed=100001`

结果如下：

- `best_return = 4.5214`
- 最优 epoch：`52`
- `test mean_reward = 0.9087`
- `bitrate = 1038.1`
- `rebuf = 0.0125`
- `smooth = 0.0757`

和原始 `hmix 100001` 对比：

- 原始 `hmix 100001`：`0.8206 / 1089.0 / 0.0426 / 0.0854`
- `v2lite 100001`：`0.9087 / 1038.1 / 0.0125 / 0.0757`

这组结果非常关键，因为 `100001` 原本就是旧版 `hmix` 掉点最明显的 seed。现在可以看到：

1. `mean_reward` 从 `0.8206` 大幅提升到 `0.9087`，增幅约 `+0.0882`。
2. `rebuf` 从 `0.0426` 显著下降到 `0.0125`，说明旧版最严重的失控问题被压住了。
3. `smooth` 也从 `0.0854` 改善到 `0.0757`。
4. `bitrate` 从 `1089.0` 回落到 `1038.1`，但这种回落是值得的，因为它换来了更合理的整体 QoE。

再和 `maskprevreward 100001` 对比：

- `maskprevreward 100001`：`0.8902 / 1050.1 / 0.0203 / 0.0728`
- `v2lite 100001`：`0.9087 / 1038.1 / 0.0125 / 0.0757`

这说明：

1. `v2lite` 在这个 seed 上也已经超过了非 TimeMixer 主线。
2. 它不是靠更激进的高码率取胜，而是通过更低的重缓冲把总体 reward 提上去。
3. 代价是 bitrate 略低、smooth 略差，但整体权衡已经优于 `maskprevreward 100001`。

### `seed=100003`

结果如下：

- `best_return = 4.5221`
- 最优 epoch：`58`
- `test mean_reward = 0.9510`
- `bitrate = 1069.7`
- `rebuf = 0.0102`
- `smooth = 0.0749`

和原始 `hmix 100003` 对比：

- 原始 `hmix 100003`：`0.9212 / 1066.5 / 0.0165 / 0.0744`
- `v2lite 100003`：`0.9510 / 1069.7 / 0.0102 / 0.0749`

这说明：

1. 这不是简单“更激进换更高码率”的提分。
2. `bitrate` 略升。
3. `rebuf` 明显下降。
4. `smooth` 基本持平。
5. 最终 QoE 的大幅提升是比较健康的提升，不像偶然尖峰。

再和 `maskprevreward 100003` 对比：

- `maskprevreward 100003`：`0.9175 / 1055.0 / 0.0132 / 0.0807`
- `v2lite 100003`：`0.9510 / 1069.7 / 0.0102 / 0.0749`

这一组结果几乎是全面占优：

1. reward 更高
2. bitrate 更高
3. rebuffer 更低
4. smoothness 更好

### 当前对 `hmix_v2lite` 的判断

现在 `hmix_v2lite` 的 3 个 seed 已经全部跑完，结论可以正式写清楚了：

1. `v2lite 100001` 修复了旧版 `hmix` 最严重的掉点 seed。
2. `v2lite 100002` 也成功修复了旧版 `hmix` 在该 seed 上的弱表现。
3. `v2lite 100003` 不但保住了高上限，还把最优结果进一步推到了 `0.9510`。
4. 对应 3-seed 均值达到 `0.9248`，显著高于原始 `hmix` 的 `0.8683`，也高于 `maskprevreward` 的 `0.9051`。

因此，`hmix_v2lite` 现在可以做出比较明确的判断：

1. 它已经不再只是“有潜力的修正版”，而是当前结果最强的完整主线。
2. 它同时提升了上限和均值。
3. 从目前 3 个 seed 的结果看，它的稳定性也明显优于原始 `hmix`。
4. 这意味着当前最合理的主结论已经从“继续验证 `v2lite` 是否可靠”变成了“以 `v2lite` 作为新的默认主线向前推进”。

## 当前建议

### 如果目标是“现在就选一条最强、已完整验证的主线”

优先用 `hmix_v2lite`。

原因：

- 它已经有 3 个完整 seed
- 3-seed 均值最高
- 当前单次最优结果也来自这条线
- 与原始 `hmix` 相比，稳定性已明显改善

### 如果目标是“下一步最值得继续投资源的方向”

优先用 `hmix_v2lite`。

原因：

- 它已经拿到了当前最优单次结果
- 已经修复了 `100001`
- 已经修复了 `100002`
- 已经显著提升了 `100003`
- 已经完成了 3-seed 验证，适合继续做后续消融和扩展

## 下一步更合理的实验方向

当前不再有“必须先补齐的验证 seed”，因为 `hmix_v2lite` 的 3 个 seed 已经完成。  
接下来更合理的是做以下几类工作：

1. 补更多 seed，进一步确认方差水平。
2. 在 `v2lite` 上做更细的结构消融，例如只改 gate、只改 scale、只改 throughput 分支。
3. 观察是否还能进一步降低 `100002` 这种偏高的 `rebuf`，同时不损失当前高 reward。
