# 基于 ABR 仓库的本科毕业设计规划与论文提纲

最后更新：`2026-05-10`

## 1. 文档用途

这份文档面向当前 `NetLLM-master/adaptive_bitrate_streaming` 仓库，目标是帮助你把已有代码、实验和改进点整理成一篇计算机科学与技术专业本科毕业设计。

它重点回答 4 个问题：

1. 毕业设计题目怎么定
2. 论文应该如何定位，才能既贴合仓库又体现你自己的工作
3. 章节提纲应该怎么写
4. 后续实验、作图、写作和答辩应该怎么安排

## 2. 推荐的选题定位

如果直接把题目写成“NetLLM 复现”，本科论文会显得偏弱，因为老师通常更希望看到“在已有框架基础上的设计、实现与优化”。

因此，更推荐把论文定位成：

> 在 NetLLM 与 ABR 仿真框架基础上，针对自适应码率决策任务，设计一种结合语义重编程、上下文对齐和历史带宽建模的智能决策方法，并完成实现与实验验证。

### 2.1 推荐题目

下面 3 个题目都可以用，推荐优先级从上到下：

1. `基于大语言模型适配的自适应码率视频传输决策方法研究与实现`
2. `基于语义重编程与历史多尺度建模的自适应码率决策优化方法研究`
3. `面向动态网络环境的智能自适应码率视频传输系统设计与实现`

### 2.2 推荐最终采用的题目

如果你希望题目稳妥、学术感和工程感兼顾，最推荐：

> `基于大语言模型适配的自适应码率视频传输决策方法研究与实现`

这个题目的好处是：

- 不会把自己限定死在某一个具体模块名上
- 可以自然包含 NetLLM 框架、语义重编程、注意力改进和历史建模
- 更符合本科毕业设计常见命名习惯

## 3. 论文应该如何定位

这篇论文不建议写成“从零提出一个全新 ABR 框架”，因为当前仓库本身继承了已有工作：

- ABR 环境与部分 baseline 来自 `Genet`
- 大模型适配的大框架来自 `NetLLM`

更合理、也更容易答辩通过的写法是：

1. 先说明本文工作建立在已有 ABR 仿真框架与 NetLLM 适配框架之上
2. 然后强调你在 ABR 子任务上做了针对性的模型设计、模块优化、实验整理与性能分析
3. 最终把贡献聚焦到“面向 ABR 任务的改进与验证”

推荐把你的工作总结为下面 4 点：

1. 搭建并梳理了完整的 ABR 实验链路，包括基线测试、经验池生成、PLM 适配训练与在线评测。
2. 在 ABR 任务上实现了语义重编程状态编码方法，使数值网络状态能够映射到大语言模型表征空间。
3. 设计了结合 `prev_action` 与 `prev_reward` 的步内预对齐机制，并探索了轻量化历史多尺度建模方法。
4. 基于 `BBA / MPC / UDR_3 / Genet` 等基线完成对比实验与消融实验，验证所提方法的有效性。

## 4. 当前仓库最适合写成“自己工作”的主线

结合当前代码和实验文档，最适合写进毕业设计的主线不是单纯复现原始 NetLLM，而是下面这条线：

### 4.1 技术主线

1. 以 `semantic_only` 作为语义重编程基线
2. 以 `maskprevreward` 作为上下文预对齐增强版本
3. 以 `hmix_v2lite` 作为轻量化历史多尺度增强版本
4. 与 `BBA / MPC / UDR_3 / Genet` 做统一比较

### 4.2 可写成创新点的内容

结合当前 `state_encoder.py` 和 `rl_policy.py`，你现在最容易写成论文创新点的是：

1. 语义重编程状态编码
2. 基于 `prev_action + prev_reward` 的预对齐步内注意力
3. 面向短历史吞吐序列的轻量化多尺度混合模块
4. 在 ABR QoE 指标下的多 seed 稳定性分析

注意这里的“创新”更适合表述为：

- `改进`
- `优化`
- `面向 ABR 场景的设计`
- `轻量化结构设计`

而不是写成“提出全新通用大模型理论”。
